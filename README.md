# Frigo (Семейное меню) · v8

Web-приложение на **обычных HTML, CSS и JavaScript**, без фреймворка и сборщика.
Интерфейс — прототип v4 (цвета, шрифты, отступы, компоненты), сценарий — v6:

- заставка Frigo → 4 слайда с прогресс-баром → знакомство из 5 шагов, на каждый нужен ответ
  (цель, тип питания, аллергии и «не нравится» с кнопкой «Ещё» после 4 строк, продукты в холодильнике,
  дни 1–7 и что готовим на каждый приём пищи) → загрузка 2 с → первое меню → вход через Telegram;
- новый аккаунт забирает меню, ответы и продукты, сделанные до входа;
- вкладки «Меню» (даты, ближайший приём пищи крупно, готовка по шагам), «Покупки» (без ссылок на магазины,
  цена корзины ведёт в Premium), «Дома» (поиск, фото холодильника с распознаванием, категории), «Профиль»;
- свои рецепты попадают в подбор меню; «второе с гарниром» собирается из основного блюда и гарнира;
- Premium — подписка: автосборка корзины под бюджет, подборка акций, калории и КБЖУ.

Код v4 перенесён на исходный стек (`src/app.js`, `src/shell.js`, `src/v4.js`), сценарий v8 — в `src/v8.js`.
Архив исходника v3 в `legacy/` сохранён для сравнения; в публикацию он не входит.

## Данные и вход

- Каталог, ингредиенты, цены, акции и словарь продуктов загружаются с backend через `/api/catalog`.
  Локального запасного каталога нет: при недоступности сервера показывается повторная загрузка.
- Вход — подтверждение в Telegram-боте. Сохранено оформление исходного экрана входа;
  имитация СМС и демо-аккаунт не используются. Приложение не получает токен бота.
- Меню и предпочтения читаются и сохраняются через `/api/user-state` с проверкой ревизии.
  Адаптер преобразует исходную модель UI в существующий контракт API, не меняя backend.
  Дополнительные поля прежних клиентов сохраняются.
- Запасы загружаются через `/api/inventory`. Добавление, изменение количества и удаление
  сохраняются на сервере; поиск ингредиента обращается к `/api/ingredients` от трёх символов.
- Личные документы не кэшируются в `localStorage`. Сессия хранится отдельно, обновляется
  через `/api/auth/refresh`; при выходе личное состояние очищается. Конфликт сохранения
  требует явной загрузки актуальных данных, без автоматической перезаписи чужих изменений.

Backend остаётся на `https://vibe-coding-sc04.onrender.com` и **не изменён** при восстановлении UI.
Его сканер, дополнительные методы, таблицы и изображения сохранены, даже если исходный UI
пока их не вызывает. Backend-ключи находятся на Render; Web не обращается напрямую в
Supabase, OpenAI или Cloud/Claude Artifacts.

## Локальный запуск Web

```sh
node scripts/serve-web.mjs
```

Сервер по умолчанию слушает порт 8080, уже разрешённый CORS backend.
Открывать приложение нужно по HTTP, а не как `file://`.
Для подготовки статической публикации:

```sh
node scripts/build-web.mjs
node scripts/serve-web.mjs _site
```

В `_site/` копируются только `index.html` и `src/`. Backend, секреты, архив и тесты
не попадают на GitHub Pages. Зависимости для браузерного приложения не устанавливаются.

## Проверки и публикация

```sh
node --test tests/web/*.test.mjs
node scripts/build-web.mjs
CHROME_BIN=chromium node scripts/web-smoke.mjs _site
```

Проверяются совместимость с неизменённым API, даты и состояния меню, обновление сессии,
изоляция аккаунтов, восстановление после перезагрузки и конфликт ревизий.
Браузерный сценарий проходит путь v8 от заставки до выхода; SVG-генератор проверяется на побайтовое совпадение с исходником. Снимки лежат в
`build/reports/web-smoke/`. Telegram и backend подменены; реальных записей и платных
запросов в этих тестах нет.

Workflow **Build Web** проверяет статический Web и публикует готовый артефакт в Pages.
Android/iOS/Gradle не запускаются. Адрес:
[ivoratrace-ux.github.io/FamilyMenu](https://ivoratrace-ux.github.io/FamilyMenu/).

## Backend и база

Backend по-прежнему запускается `npm start`, его тесты — `npm test`.
Миграции запускаются отдельно и не выполняются при старте API.
