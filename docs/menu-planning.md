# Подбор семейного меню

Подбор выполняется в Web-клиенте. Диета, аллергии, исключённые и любимые продукты,
цели питания остаются общими для семьи. Личных пищевых предпочтений нет.

## Калории и количества

Норма каждого человека рассчитывается существующей функцией `need` или задаётся
вручную. Индивидуальный коэффициент порции — точное `need / 2200`, без прежнего
округления до десятых и ограничения 0.4–1.6. Количество для приготовления равно
сумме коэффициентов всех членов семьи, умноженной на размер порции конкретного блюда.
Список покупок и экран приготовления используют это же количество.

После первоначального выбора день балансируется к 2200 ккал базового меню.
Следовательно, каждый человек получает свою норму через свой коэффициент. Размеры
блюд меняются в пределах 0.25–2.5 базовых порций. При нескольких блюдах сохраняются
все выбранные пользователем виды блюд; автоматические перекусы добавляются отдельно.
Уже приготовленные/съеденные блюда балансировка не меняет.

При удешевлении сравнивается стоимость эквивалентного количества калорий. Каждая
замена проверяется по фактической стоимости списка с целыми упаковками и имеющимися
запасами. Затем калории проверяются снова. Автоматический перекус можно убрать,
только если остальные блюда покрывают норму и покупка действительно дешевеет.
Если найти меню в бюджете не удалось, пользователь видит превышение, в том числе
до входа после онбординга. Нехватка калорий не используется для скрытого удешевления.
Если выбранных блюд недостаточно даже при максимальной порции, показывается
предупреждение о дефиците более 10%; предлагают добавить приём пищи или изменить
ограничения. Алгоритм эвристический и не доказывает невозможность более дешёвого меню.

В заголовке дня показываются калории на семью (для одного человека — его калории).
Индивидуальные значения сохраняются в дневнике, калории блюда указаны для базовой
порции с применённым множителем.

## Разнообразие

Выбор вероятностный среди до 16 подходящих кандидатов в диапазоне оценок лучшего.
Высокая оценка повышает вероятность, но не фиксирует победителя. Два предыдущих меню
дают мягкий штраф повторяющимся блюдам. История хранится в предпочтениях текущего
пользователя. Аллергии, диета и исключения остаются обязательными фильтрами.
Гарниры из имеющихся продуктов сохраняют приоритет. «Без повторений» относится к
текущему меню; основной продукт с разными гарнирами учитывается как одно блюдо.
При очень ограниченном ассортименте и бюджете разнообразие естественно ниже.

## Сохранение и проверки

`menu.days[].slots[].servings` теперь допускает положительное дробное число до 100.
Формат JSON и методы API не менялись, миграции БД не нужны. Рецептурное поле servings
в каталоге не изменяется. Множители блюд (`parts8`) сохраняются в предпочтениях вместе
с текущим меню. При выборе лучшего варианта из нескольких сохраняется соответствующий
набор множителей, а не множители последней попытки.

Целевые проверки: `tests/web/state.test.mjs`, `backend/tests/user-state.test.mjs`
и браузерный `scripts/web-smoke.mjs`. Последний проверяет нормы взрослого 4000 и ребёнка
1400 ккал, наличие запасов, малый бюджет, общие аллергии/исключения, пересборки и
восстановление дробных порций после сохранения.
