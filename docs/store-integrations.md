# ВкусВилл: публичная корзина

Ветка `feature/vkusvill-cart`, синхронизирована с UI v8.6 из `bde48de`.

В «Покупках» кнопка «Сформировать корзину во ВкусВилле» запускает подбор. После готовности
появляется кнопка «Добавить в корзину», открывающая ссылку магазина только по нажатию. Промежуточной проверки товаров в Frigo нет.
Только недостающие количества: позиции «куплено» и полностью покрытые запасами
исключаются. Специи без количества не добавляются. Создание корзины не меняет
запасы, меню, предпочтения и отметки покупок.

## Контракт

`POST /api/stores/vkusvill/cart`, необходим bearer текущего пользователя Frigo:

```json
{"items":[{"ingredientId":"milk","quantity":1500}]}
```

Единицы — из каталога Frigo (`g`, `ml`, штуки и т. д.). Backend проверяет ID,
дубли и количества; названия и единицы берёт из своего каталога.
Публичный MCP `https://mcp.vkusvill.ru/mcp` подключается через Streamable HTTP,
без OAuth ВкусВилла. Обрабатываются JSON и SSE, MCP-сессии и список инструментов.
Поиск `vkusvill_products_search` выполняется максимум тремя запросами одновременно.

Из реальных кандидатов OpenAI на backend подбирает соответствующий товар и число
упаковок/количество в единицах продажи. Используется существующий `OPENAI_API_KEY`
на Render. Модель не создаёт ссылки: backend проверяет выбранные числовые ID на наличие
в результатах поиска (`ok:true`, `data.items`) и вызывает `vkusvill_cart_link_create` с `products: [{id,q}]`.
Один и тот же ID объединяется. При отсутствии продукта или неопределённой
фасовке весь запрос завершается 422, без молчаливого удаления позиций.

Ответ:

```json
{"store":"vkusvill","carts":[{"url":"https://vkusvill.ru/mobile?basket&share=68154","productCount":1}],"ingredientCount":1,"productCount":1}
```

На актуальной странице сервера указан лимит 100 товаров, ID — положительное целое,
количество `q` — от 0.01 до 40 единиц продажи на товар. Весь список отправляется
одним вызовом создания корзины. Превышение количества завершается ошибкой,
без молчаливого уменьшения. Ограничение 20 позиций и `xml_id` из старой статьи
больше не используются. При формировании корзины вкладки не открываются. Готовая ссылка отображается
как кнопка «Добавить в корзину». При выходе, смене аккаунта или списка
устаревшая ссылка не показывается. Все ссылки берутся только из ответа cart tool;
разрешены HTTPS-домены ВкусВилла и `vkusvill.onelink.me`.

Ограничения: до 100 ингредиентов в запросе, 150 секунд на сервере, две сборки
одновременно, до 10 сборок на пользователя и 30 суммарно в час на экземпляр.
Это публичный каталог: наличие по адресу доставки, состав, цены, оформление
и оплату пользователь проверяет во ВкусВилле. Приложение откроется, если возвращённая
магазином ссылка поддерживает его на устройстве; иначе откроется сайт.

## Проверка доступа

```sh
NODE_USE_ENV_PROXY=1 node scripts/check-vkusvill.mjs
```

Можно запустить ту же команду в Render Shell из checkout этой ветки. Скрипт
выполняет только initialize / tools/list / поиск молока, без аккаунтов, корзин,
записей в базу и OpenAI. При успешном подключении печатает актуальную схему cart tool.

23 октября 2026 публичный MCP проверен из сети GitHub Actions без OAuth:
initialize, tools/list, поиск молока и создание настоящей анонимной корзины прошли
с HTTP 200. Получена ссылка `https://vkusvill.ru/mobile?basket&share=68154`.
[Успешный запуск](https://github.com/ivoratrace-ux/FamilyMenu/actions/runs/39906662259).
Ни заказ, ни оплата не выполнялись. Открытие мобильного приложения
остаётся отдельной проверкой на устройстве. Полный подбор фасовок через OpenAI
дополнительно проверен через развёрнутый backend, как описано ниже.

Диагностика из сети GitHub Actions запускается вручную без ключей:

```sh
gh workflow run backend.yml --ref feature/vkusvill-cart -f probe_vkusvill=true -f probe_cart=true
```

Этот режим пропускает сборку и production deploy. `probe_cart=true` дополнительно
создаёт публичную тестовую корзину с одной единицей молока; без него выполняются
только инициализация, список инструментов и поиск.

`GET /health/vkusvill` независимо проверяет подключение к публичному MCP из сети
backend. Ответ содержит только `status` и `publicMcp`; проверки объединяются и
кешируются на минуту. Запрос не обращается к OpenAI, не ищет товары и не создаёт
корзину. Недоступность ВкусВилла не меняет основной `/health` и вход в приложение.

### Результат расследования 403

- Актуальная страница `https://mcp.vkusvill.ru/mcp` получена через публичный
  reader из другой сети (`https://r.jina.ai/https://mcp.vkusvill.ru/mcp`, без кеша).
  Она явно говорит: «Для работы с публичными инструментами добавьте ссылку на
  MCP-сервер своему ИИ-помощнику». OAuth описан отдельно, для полного функционала.
  На странице также указан новый контракт корзины: `products(1..100)`, `{id,q}`.
- В конфигурации cloud network policy — `unrestricted`. Не обнаружено ограничения
  по списку разрешённых доменов, которое требовало бы менять настройки окружения.
- `vkusvill.ru/oauth/registration/` и
  `oauth.vkusvill.ru/.well-known/oauth-authorization-server` доступны из этой же сети
  (HTTP 200). Только MCP-домен возвращает HTML блокировки: GET страницы,
  POST initialize, discovery. Заголовка `WWW-Authenticate` нет.
- Обычный браузерный User-Agent, корректный JSON-RPC initialize, заголовки MCP,
  same-origin Origin и анонимные cookies основного сайта результат не меняют.
- Это указывает на фильтрацию доступа к MCP-домену до получения MCP-ответа,
  вероятно по исходящему IP/сети или признакам клиента. Точное правило фильтра
  извне не установлено; отсутствие OAuth само по себе эту HTML-блокировку
  не объясняет. Успешные initialize, поиск и корзина из GitHub Actions на том же
  клиенте подтвердили, что публичный режим работает, а ограничение зависит от сети.

Для воспроизведения из cloud можно использовать диагностический скрипт. Пример
support ID для обращения к ВкусВиллу: `01a1673e-1178-7030-a221-a6a4c9d20182`
(23 октября 2026, POST initialize, служебный код страницы `94-01`). Скрипт печатает
новый ID для каждого воспроизведения, HTTP status, тип ответа и наличие auth challenge.

Для проверки из Render используется `/health/vkusvill` после развёртывания коммита
этой ветки через deploy hook с параметром `ref`. Это позволяет сохранить ветку
`main` и опубликованный Web без изменений. Развёрнут коммит `6f21376f73f7bee5aac6c1b84ba1486df5fcf1be`,
`GET /health/vkusvill` вернул HTTP 200 с `publicMcp: available`.

### Полная живая проверка backend

23 октября 2026 выполнен авторизованный POST `/api/stores/vkusvill/cart` на Render:
молоко 1500 мл, картофель 1200 г и яйца 4 шт. Получен HTTP 200, три ингредиента,
три товара, одна корзина: `https://vkusvill.ru/mobile?basket&share=68158`.
Прошла реальная цепочка Supabase Auth → каталог → публичный MCP → OpenAI → MCP cart.
Запасы, меню и предпочтения, загруженные через API до и после, побайтово совпали.
Для проверки создана изолированная временная учётная запись без отправки почты;
после проверки она удалена вместе с профилем. Данные действующих пользователей
не использовались. Заказ и оплата не выполнялись.

Локально прошли 44 целевых теста и браузерный сценарий актуального UI v8.6.
Backend и Web CI также прошли. Ветка `main`, backup-ветка и Pages не изменялись.
