# ВкусВилл: публичная корзина

Ветка `feature/vkusvill-cart`, основа — UI v8 из `f105e57`.

В «Покупках» кнопка «Сформировать корзину во ВкусВилле» сразу запускает подбор
и открывает ссылку магазина. Промежуточной проверки товаров в Frigo нет.
Только недостающие количества: позиции «куплено» и полностью покрытые запасами
исключаются. Специи без количества не добавляются. Создание корзины не меняет
запасы, меню, предпочтения и отметки покупок.

## Контракт

`POST /api/stores/vkusvill/cart`, необходим bearer текущего пользователя Frigo:

```json
{"items":[{"ingredientId":"milk","quantity":1500}]}
```

Единицы — из каталога Frigo (`g`, `ml`, штуки и т. д.). Backend проверяет ID,
дубли и количества; названия и единицы берёт из своего каталога.
Публичный MCP `https://mcp.vkusvill.ru/mcp` подключается через Streamable HTTP,
без OAuth ВкусВилла. Обрабатываются JSON и SSE, MCP-сессии и список инструментов.
Поиск `vkusvill_products_search` выполняется максимум тремя запросами одновременно.

Из реальных кандидатов OpenAI на backend подбирает соответствующий товар и число
упаковок/количество в единицах продажи. Используется существующий `OPENAI_API_KEY`
на Render. Модель не создаёт ссылки: backend проверяет выбранные числовые ID на наличие
в результатах поиска и вызывает `vkusvill_cart_link_create` с `products: [{id,q}]`.
Один и тот же ID объединяется. При отсутствии продукта или неопределённой
фасовке весь запрос завершается 422, без молчаливого удаления позиций.

Ответ:

```json
{"store":"vkusvill","carts":[{"url":"https://vkusvill.ru/?share_basket=123","productCount":1}],"ingredientCount":1,"productCount":1}
```

На актуальной странице сервера указан лимит 100 товаров, ID — положительное целое,
количество `q` — от 0.01 до 40 единиц продажи на товар. Весь список отправляется
одним вызовом создания корзины. Превышение количества завершается ошибкой,
без молчаливого уменьшения. Ограничение 20 позиций и `xml_id` из старой статьи
больше не используются. Ссылка открывается автоматически. Если браузер блокирует новую вкладку,
готовая ссылка также остаётся на экране. При выходе, смене аккаунта или списка
устаревший ответ не открывается. Все ссылки берутся только из ответа cart tool;
разрешены HTTPS-домены ВкусВилла и `vkusvill.onelink.me`.

Ограничения: до 100 ингредиентов в запросе, 150 секунд на сервере, две сборки
одновременно, до 10 сборок на пользователя и 30 суммарно в час на экземпляр.
Это публичный каталог: наличие по адресу доставки, состав, цены, оформление
и оплату пользователь проверяет во ВкусВилле. Приложение откроется, если возвращённая
магазином ссылка поддерживает его на устройстве; иначе откроется сайт.

## Проверка доступа

```sh
NODE_USE_ENV_PROXY=1 node scripts/check-vkusvill.mjs
```

Можно запустить ту же команду в Render Shell из checkout этой ветки. Скрипт
выполняет только initialize / tools/list / поиск молока, без аккаунтов, корзин,
записей в базу и OpenAI. При успешном подключении печатает актуальную схему cart tool.

На 22 октября 2026 cloud-окружение получает HTML `403 Access Blocked` даже для
корректного initialize, страницы сервера и resource discovery на MCP-домене.
Доступ из Render ещё не проверен. Живой контракт поиска/корзины и открытие приложения
**не подтверждены**; локальные проверки используют актуальное описание сервера
и подменённые ответы.
Публикация этой ветки в production и проверка из Render ещё не выполнялись.

### Результат расследования 403

- Актуальная страница `https://mcp.vkusvill.ru/mcp` получена через публичный
  reader из другой сети (`https://r.jina.ai/https://mcp.vkusvill.ru/mcp`, без кеша).
  Она явно говорит: «Для работы с публичными инструментами добавьте ссылку на
  MCP-сервер своему ИИ-помощнику». OAuth описан отдельно, для полного функционала.
  На странице также указан новый контракт корзины: `products(1..100)`, `{id,q}`.
- В конфигурации cloud network policy — `unrestricted`. Не обнаружено ограничения
  по списку разрешённых доменов, которое требовало бы менять настройки окружения.
- `vkusvill.ru/oauth/registration/` и
  `oauth.vkusvill.ru/.well-known/oauth-authorization-server` доступны из этой же сети
  (HTTP 200). Только MCP-домен возвращает HTML блокировки: GET страницы,
  POST initialize, discovery. Заголовка `WWW-Authenticate` нет.
- Обычный браузерный User-Agent, корректный JSON-RPC initialize, заголовки MCP,
  same-origin Origin и анонимные cookies основного сайта результат не меняют.
- Это указывает на фильтрацию доступа к MCP-домену до получения MCP-ответа,
  вероятно по исходящему IP/сети или признакам клиента. Точное правило фильтра
  извне не установлено; отсутствие OAuth само по себе эту HTML-блокировку
  не объясняет. Документация не подтверждает закрытие публичного режима,
  но успешного initialize из доступной нам сети пока нет.

Следующая необходимая проверка — этот диагностический скрипт из сети Render.
У доступного deploy webhook нет возможности выполнить shell-команду; Render API/SSH
доступа в окружении нет. При обращении к ВкусВиллу можно передать support ID
`01a1657e-6bda-7c85-bb58-5c1b7b8bab62` (22 октября 2026, 21:22:25 UTC,
POST initialize, служебный код страницы `94-01`). Скрипт печатает новый ID для
каждого воспроизведения, HTTP status, тип ответа и наличие auth challenge.
