# Контракт интеграции сканера

Приложение использует уже развёрнутый Node.js backend из `vibe_coding-main.zip`:
`https://vibe-coding-sc04.onrender.com/api/fridge/scan`.

## Поток данных

Камера/галерея → локальное уменьшение и JPEG → JSON с Base64 → Render → OpenAI
`gpt-4.1-mini` → проверка результата сервером → проверка результата общим Kotlin-клиентом
→ временный список на экране «Дома».

Подтверждение альтернатив и удаление изменяют только этот временный список.
Вызовов Supabase, endpoint генерации рациона и сохранения фото здесь нет.
Ключи OpenAI/Supabase остаются в существующем окружении Render.

## Обязательное изменение существующего Render для Web

В переменную `ALLOWED_ORIGINS` добавить `https://ivoratrace-ux.github.io`, сохранив
старые значения. Например, если сейчас разрешён только старый веб-клиент:

```
ALLOWED_ORIGINS=https://pobazar.github.io,https://ivoratrace-ux.github.io
```

Применить конфигурацию на том же сервисе. Это не требует переноса ключей.
Для локальной Web-разработки добавить фактический origin dev-сервера, если он
ещё не разрешён. Не использовать wildcard для обхода настройки.

Проверка `node scripts/check-scan-backend.mjs` выполняет OPTIONS и POST с пустым
объектом, ожидая 204 и 400. Расходов OpenAI и отправки фото нет. Настоящее
распознавание нужно отдельно проверить реальной фотографией после настройки CORS.

## Обработка ошибок

Клиент ограничивает размер до 4 МБ и ожидает до 150 секунд, включая пробуждение Render.
Сервер может вернуть 429 при общем лимите 30 сканирований в час или двух активных
запросах. Эти лимиты заданы на существующем backend и не изменены новым приложением.
Произвольные тела ошибок сервера не показываются пользователю.
