# Загрузка приложения

Сплэш декоративный: минимум 700 мс и 150 мс на завершение анимации. Сеть не продлевает его; загрузка самих JS-файлов всё ещё необходима для запуска интерфейса.

При первом запуске вводные слайды доступны без каталога. Параллельно начинается `GET /api/catalog?view=web`, необходимый локальному подборщику меню. Переход к вопросам о предпочтениях ждёт этот запрос; при ошибке здесь появляется повторная попытка. Иллюстрации слайдов не требуют данных рецептов.

Для вошедшего пользователя:

- `frigo-startup-v2` в localStorage содержит ID владельца, версии меню/настроек и запасов, их снимки и данные только нужных рецептов/ингредиентов. Он отображается до ответа сети.
- `GET /api/startup` проверяет пользователя один раз и возвращает `{userId, document, inventory, catalog}`. В `catalog` входят рецепты текущего меню, основы комбинаций/изменённых рецептов и используемые ингредиенты, включая продукты из запасов. Полные foods/promos не отправляются.
- Фоновая проверка кэша передаёт `revision` и `inventoryRevision`. При совпадении API возвращает только `{userId, unchanged: true}`, без чтения каталога и повторной передачи меню. Более свежий снимок применяется, если за время запроса пользователь не успел изменить локальные данные. Версии продолжают защищать сохранение от конфликтов.
- Кэш обновляется после успешного сохранения; при выходе очищаются данные приложения из localStorage/sessionStorage, загруженные рецепты/ингредиенты из памяти. Поздние ответы старого запуска игнорируются. HTTP-кэш браузера с публичными статическими файлами не содержит личных данных и программно не очищается.

Остальные данные загружаются по требованию:

- `GET /api/recipes?kind=soup` — варианты одной категории; `pair` включает основные блюда и гарниры.
- `GET /api/recipes?ids=b1,m3` — конкретные рецепты, например из избранного/истории.
- `GET /api/recipes?q=творог` — поиск блюд и продуктов для дневника, от двух символов.
- `GET /api/catalog/ingredients` — справочник для выбора продуктов/ограничений и редактирования рецептов, без остальных рецептов.
- Полный каталог нужен для составления/пересборки меню и существующих экранов общего справочника питания/акций; обычное открытие меню его не запрашивает.

Каталог Supabase остаётся каноническим. Дополнительные рецепты и ингредиенты из `src/extra8.js` теперь объединяются на сервере: их общая декларация используется полными и частичными ответами. Пометка `client` сохраняет прежнее хранение дополнительных запасов в предпочтениях, отдельно от inventory RPC. Старый `GET /api/catalog` без `view=web` не меняет контракт.

Проверки: `tests/web/bootstrap.test.mjs`, `tests/web/startup-cache.test.mjs`, `backend/tests/startup.test.mjs` и браузерный `scripts/web-smoke.mjs` (ошибка каталога не блокирует слайды, восстановление кэша при задержке API, старт без полного каталога, подгрузка замен и выход).
